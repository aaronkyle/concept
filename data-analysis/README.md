# data analysis

Data analysis is the work of examining evidence in relation to a question. It may involve counting, comparing, classifying, mapping, modeling, or close reading, but no method becomes meaningful until we can explain why it was chosen and what its result permits us to conclude.

The discussions in this section begin with two themes:

- [analysis as a research process](analysis-as-a-research-process.md) connects questions, evidence, preparation, interpretation, and communication; and
- [reproducible and collaborative analysis](reproducible-and-collaborative-analysis.md) considers what a team must preserve so that an analysis can be understood, reviewed, and revised.

These concerns cut across the site. [Data capture](../data-capture/) considers how source material enters the system, [data structures](../data-structures/) considers how it is described and organized, and [data visualization](../data-visualization/) and [digital publishing](../digital-publishing/) consider how findings are communicated.

## boundary with data capture

Recovering text, metadata, or structure from a source file prepares material for analysis but does not, by itself, interpret that material. See [extracting text and data from files](../data-capture/extracting-text-and-data-from-files.md) for the intake and extraction discussion. An analysis should retain a link to that earlier work so that a reader can distinguish the source, machine-produced observations, later corrections, and analytical judgments.
